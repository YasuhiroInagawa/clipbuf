# Implementation Plan

> 開発・検証は macOS 上で行う。Windows / Linux 固有の実装は「CI の該当 OS でビルドとテストが通る」ことを完了条件とし、実機（VM）での動作確認は `doc/platform-checklist.md` に従って節目で別途行う（本タスク一覧には含めない）。

- [ ] 1. 基盤: 開発環境・プロジェクト雛形・CI・共有契約
- [x] 1.1 Rust 開発環境を準備する
  - rustup で Rust stable（edition 2024 対応）を導入し、シェルの PATH に `cargo` を通す
  - Tauri 2 の macOS 前提（Xcode Command Line Tools）が揃っていることを確認する
  - 新しいシェルで `cargo --version` と `rustc --version` が表示される
  - _Requirements: 11.1_

- [x] 1.2 Tauri 2 + Svelte 5 + TypeScript のプロジェクト雛形を作成する
  - `npm run tauri dev` で空のメインウィンドウが起動し、常に最前面・タスクバー非表示・全ワークスペース表示・リサイズ可（最小 360×240）である
  - 仮の識別子（例: `jp.gr.mac.iyas.clipbuf`）と製品名 `clipbuf` を設定する（最終名はリリース前に確定）
  - CSP を `default-src 'self'` とし、外部リソースを読み込まない
  - Rust 側に設計どおりの空モジュール構成（model / analysis / transform / buffer / clipboard / settings / app）を置き、`cargo clippy -- -D warnings` と `cargo fmt --check` が通る
  - Frontend に ESLint + Prettier + Vitest を設定し、`npm run lint` と `npm test`（サンプルテスト 1 件）が通る
  - _Requirements: 8.1, 8.7, 10.3, 10.4_

- [x] 1.3 3 OS の CI ワークフローを構築する
  - push / pull_request で ubuntu / windows / macos の 3 ジョブが走り、Linux は webkit2gtk・gtk3・appindicator・librsvg・xcb の依存を導入する
  - 各ジョブで lint、Vitest、`cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test`、`cargo build` を実行する
  - 3 ジョブすべてが緑になった状態で main に取り込まれている
  - _Requirements: 11.1_

- [x] 1.4 Rust と frontend で共有する型契約を定義する
  - 項目・警告 7 種・転送オプション（改行モード 3 択を含む）・転送モード・設定（既定値と許容範囲を含む）・転送結果・エラー種別を Rust の型として定義し、camelCase の JSON に serde 化する
  - 同じ形の TypeScript 型を frontend 側に定義する
  - Rust → frontend のイベント名（項目追加・一覧変更・設定変更・表示・取り込み状態）と payload の対応を定数として定義する
  - Rust の serde 往復テストと、代表値の JSON が TypeScript 型と一致することを確認するテストが通る
  - 設定の既定値が「保持件数 20、ホットキー Alt+Shift+V、タブ幅 4、ポーリング 200ms、自動起動なし、言語 OS 追従、転送オプションすべて無効」である
  - _Requirements: 2.6_

- [ ] 2. コア純粋ロジック（OS・Tauri 非依存）
- [x] 2.1 (P) 不可視文字の分類表と警告判定を実装する
  - 空白・全角空白・タブ・改行・NBSP・ゼロ幅・双方向制御・制御文字の分類表を定義する（frontend と同一内容）
  - 7 種の警告判定を 1 警告 1 関数で実装する：スタイル有無、先頭末尾の空白・改行、タブ、機種依存文字（Shift_JIS エンコード結果が CP932 拡張範囲）、制御文字・U+FFFD、改行コード混在、BOM・双方向制御・NFC/NFD 混在
  - 表駆動テストで各警告の「該当 / 非該当 / 境界」が通る。例: ①・㈱・髙 で機種依存が真、é・😀・漢 で偽。CRLF+LF で混在が真、CRLF のみで偽。純 NFD は正規化混在が偽
  - 判定結果は重複なく宣言順で返る
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 5.7_
  - _Boundary: analysis_

- [x] 2.2 (P) 転送時テキスト変換を実装する
  - 改行処理（そのまま / 削除 / 空白置換。CRLF は 1 つとして扱う）、タブ→指定個数の空白、全角空白→半角空白、先頭末尾トリムを実装する
  - 適用順が「改行処理 → タブ変換 → 全角空白変換 → トリム」であることを複合入力のテストで確認する
  - 変換が 1 つも有効でない場合は入力と等しい文字列を返し、入力を変更しない
  - _Requirements: 7.7, 7.8, 7.9, 7.10, 7.11, 7.12, 6.9_
  - _Boundary: transform_

- [x] 2.3 (P) 取り込み項目の FIFO バッファを実装する
  - 新しい順の保持、上限超過時の最古削除、先頭項目と同一テキストの重複排除、個別削除、全削除、上限変更時の切り詰めを実装する
  - 項目 ID は単調増加で再利用しない
  - 永続化コードを持たず、メモリ上のみで動作する
  - 上記すべてのテストが通る
  - _Requirements: 1.6, 2.1, 2.2, 2.3, 2.4, 2.5, 10.1, 10.2_
  - _Boundary: Buffer_

- [x] 2.4 (P) frontend のプレビュー用トークン化を実装する
  - テキストを「通常文字列 / 空白 / 全角空白 / タブ / 改行 / NBSP / ゼロ幅 / 双方向制御 / 制御文字」のトークン列に変換する。CRLF は 1 つの改行トークン
  - 先頭 20,000 文字で打ち切り、打ち切ったことを返す
  - 分類表は 2.1 と同じ入力表を使い、Vitest で各分類と打ち切りが通る
  - _Requirements: 3.2, 3.4, 3.5, 3.6_
  - _Boundary: preview/tokenize_

- [ ] 3. クリップボードのポートとアダプタ
- [x] 3.1 クリップボードの抽象インターフェースとテスト用フェイクを定義する
  - 監視開始・読み取り・書き込み・取り込み能力（完全 / XWayland 限定 / 不可 / 拒否）を持つインターフェースを定義する
  - 自己書き込みマーカーの形式名（macOS / Windows / X11・Wayland）と、秘匿マーク形式名 3 種の一覧を定義する
  - 任意のスナップショットと変化を注入でき、書き込み履歴を返すフェイク実装を用意する
  - フェイクを使ったテストで、マーカー付き・秘匿マーク付きスナップショットがそれぞれ識別できる
  - _Requirements: 1.4, 1.5_

- [x] 3.2 clipboard-rs ベースのアダプタを実装する（Windows / macOS / X11）
  - 変化監視（Windows はリスナー、macOS は changeCount ポーリング、X11 は XFixes）を開始し、変化のたびにイベントを送る。内容の読み取りは変化時のみ行う
  - 読み取り時に利用可能な形式一覧を取得し、テキスト・HTML・RTF・秘匿マーク・自己マーカーの有無をスナップショットに反映する
  - 書き込み時にテキスト・（あれば）HTML/RTF・自己マーカー形式を同時に載せる
  - macOS で他アプリからコピーすると 1 秒以内にイベントとスナップショット（書式付きコピーでは HTML/RTF を含む）が得られ、自身の書き込み直後のスナップショットにマーカーが立つ
  - Windows / Linux(X11) のコードが CI でビルドされる
  - _Requirements: 1.1, 1.2, 1.8, 11.3_

- [x] 3.3 (P) Wayland 対応を有効化する（Linux のみ）
  - `clipboard-rs` の `wayland` feature を有効にし、Linux では `WAYLAND_DISPLAY` の有無でクレートが Wayland（data-control）/ X11 を実行時に選ぶ構成にする
  - 取り込み能力の判定を、クレートが選んだバックエンドに基づいて確定する（Wayland → 完全、X11 かつ Wayland セッション → XWayland 限定、X11 のみ → 完全）
  - 書き込み時のマーカー・秘匿マークは MIME 名（`application/x-clipbuf-marker` 等）で扱われ、`available_formats` に現れる
  - Linux 以外のビルドに影響せず、CI の Linux ジョブで `wayland` feature 込みのビルドとテストが通る
  - _Requirements: 11.4_
  - _Boundary: ClipboardRsAdapter_

- [ ] 3.4 アダプタ選択とプラットフォーム情報を実装する
  - Linux では「data-control 利用可 → Wayland」「X11 利用可 → clipboard-rs（XWayland 時は取り込み限定と報告）」「どちらも不可 → 取り込み不可」の順で選択する
  - macOS では起動時にペーストボードの許可状態を確認し、拒否なら「拒否」と報告する
  - OS・ディスプレイサーバ・取り込み能力をまとめたプラットフォーム情報を返す
  - macOS の実行で「完全」、Linux の選択ロジックは環境変数を差し替えた単体テストで 4 分岐が通る
  - _Depends: 3.2, 3.3_
  - _Requirements: 11.5, 11.6_

- [ ] 4. 設定とアプリ実行時の配線
- [ ] 4.1 設定の永続化ストアを実装する
  - 設定をアプリデータディレクトリの JSON に保存・復元する。項目内容は含めない。スキーマバージョンを併記し、欠損キーは既定値、不正値は既定値に置換する
  - 更新時に範囲検証を行い、失敗時は保存せずエラーを返す。成功時はどの項目が変わったかの差分を返す
  - 転送オプションのトグル状態が設定の一部として保存され、再起動後に復元される
  - 保存・復元・検証・差分のテストが通る
  - _Requirements: 7.3, 9.2, 2.6_

- [ ] 4.2 取り込みサービスを実装する
  - 監視イベントを専用スレッドで受け、100ms のデバウンス後に読み取る
  - テキストなし → 秘匿マーク → 自己マーカー → 直前の書き込み内容とのハッシュ一致、の順で除外し、残ったものを判定してバッファへ追加、追加できたら項目追加イベントを送出する
  - ウィンドウの表示状態に関係なく動作する。読み取り失敗は無視し、連続 5 回で取り込み状態イベントを送る
  - 取り込んだ内容をログに出力しない
  - フェイクを使った統合テストで、除外 4 パターンで追加されず、通常テキストで 1 回だけ追加イベントが出る
  - _Requirements: 1.1, 1.3, 1.4, 1.5, 1.7, 1.8, 10.1, 10.5_

- [ ] 4.3 frontend 向けコマンドとイベントを実装する
  - 一覧取得、転送（オプション / プレーン / 元のまま）、個別削除、全削除、設定取得・更新、プラットフォーム情報取得、ウィンドウ非表示のコマンドを提供する
  - 転送は「スタイル保持が有効・項目に書式あり・テキスト変換が有効」の場合は元のまま書き込み変換未適用を返し、それ以外は転送時点の設定でテキスト変換を適用して書き込む。書式なし項目には変換を適用する。書き込み前に内容ハッシュを記録する
  - 転送はバッファの項目を変更せず、ウィンドウ状態も変更しない
  - 設定更新コマンドは検証・保存して差分を返し、差分の適用は 4.5 が行う
  - エラーは種別のみを返し、項目内容や OS のエラー文字列を含めない
  - フェイクを使った統合テストで転送 4 分岐の書き込み内容・マーカー・結果が正しく、転送後にバッファが不変である
  - _Requirements: 2.3, 2.4, 6.5, 6.6, 6.8, 6.9, 6.10, 7.2, 7.4, 7.5, 7.6, 10.5_

- [ ] 4.4 ウィンドウ・トレイ・ホットキーを配線する
  - トレイ（macOS はメニューバー）に「表示/非表示」「設定」「終了」を置き、左クリックで表示切替する。macOS は Dock に出さない
  - グローバルホットキーで表示切替し、表示時にフォーカスと「表示された」イベントを送る。ホットキーの登録は既存を解除してから行い、失敗時は直前の登録を復元してエラーを返す
  - ウィンドウを閉じる操作は非表示にする。設定ウィンドウは初回要求時に別ウィンドウとして生成する
  - macOS の実行でトレイ・ホットキー・閉じる＝非表示が動作し、無効なホットキー文字列で直前のホットキーが効き続ける
  - _Requirements: 8.2, 8.3, 8.4, 8.5, 9.4_

- [ ] 4.5 常駐機能と設定差分の適用を配線する
  - 単一インスタンスで、2 つ目の起動は既存ウィンドウを表示する
  - `--hidden` 引数で非表示起動し、自動起動設定でこの引数を使う
  - ウィンドウの位置とサイズを保存し再起動後に復元する
  - 設定更新の差分に応じてホットキー再登録・自動起動の切替・バッファ上限の切り詰めを行い、設定変更イベントを送る
  - ホットキーに差分がある場合は保存前に登録を試み、失敗時は保存せず直前の設定を維持してエラーを返す（4.3 の検証と 4.4 の登録をこのタスクで結合する）
  - macOS の実行で位置復元・`--hidden` 起動・2 重起動時の表示・設定変更の即時反映が動作する
  - _Depends: 4.1, 4.3, 4.4_
  - _Requirements: 2.5, 8.6, 9.3, 9.4, 9.5_

- [ ] 5. Frontend
- [ ] 5.1 IPC ラッパー・ストア・i18n を実装する
  - コマンドとイベントを型付きで包み、コンポーネントが Tauri API を直接呼ばない構造にする。エラーは種別で判別できる
  - 項目一覧（初期取得 + 追加 / 置換イベント）、選択（上下移動、端の挙動、削除時の隣接選択、表示イベントで先頭選択）、設定の写し（トグル変更を即時保存、失敗時は元に戻す）のストアを実装する
  - 日本語・英語の文言リソースと `t(key)` を用意し、初期言語は設定があればそれ、なければ OS 言語が日本語なら日本語・それ以外は英語とする
  - ストアと i18n の Vitest が通る
  - _Requirements: 6.3, 7.3, 8.3, 12.1, 12.2, 12.3_

- [ ] 5.2 (P) 1 行プレビューと警告アイコン列を実装する
  - プレビューは等幅フォントでトークンを記号・色分け描画し、幅を超える分は横スクロールできる。編集不可、文字列選択・コピー不可、フォーカスが外れたらスクロール位置を先頭に戻す。打ち切り時は末尾に省略記号
  - 警告アイコン列は該当する警告だけを固定順で描画し、ホバーで i18n の説明を表示する
  - Vitest で「該当警告のみ描画」「フォーカス喪失で scrollLeft が 0」が通り、手動確認で改行・タブ・全角空白を含む項目が 1 行で記号表示される
  - _Requirements: 3.2, 3.3, 3.4, 3.5, 3.6, 4.1, 4.2, 4.3, 4.4, 5.8, 5.9_
  - _Boundary: PreviewLine, WarningIcons_

- [ ] 5.3 (P) 転送オプションのトグル列と一時通知を実装する
  - トグル列（スタイル保持、改行 3 択、トリム、タブ変換、全角空白変換）を常時表示し、変更を設定ストア経由で即時保存する。スタイル保持が有効なとき他のトグルに「書式付き項目には適用されない」ヒントを出す（無効化はしない）
  - 一時通知（成功 / 情報 / エラー）を実装し、自動で消える
  - 手動確認でトグル変更が再起動後も残り、通知が表示・消去される
  - _Requirements: 7.1, 7.3_
  - _Boundary: TransferOptions, Notice_

- [ ] 5.4 項目リストとメインウィンドウの操作を組み立てる
  - 各項目を 1 行（プレビュー + 警告列）で描画し、行クリックでオプション転送、ホバーで「プレーンで転送」「元のまま転送」ボタン、転送成功で短時間ハイライト、変換未適用・失敗は通知に渡す
  - キーボード操作（↑↓ 選択、Enter でオプション転送、Shift+Enter でプレーン転送、Delete で削除、Escape で非表示）を実装する
  - 取り込み状態イベントを受け、取り込み不可・限定・拒否のときに恒常バナーで案内を出す（macOS は設定手順、Linux は Wayland 制約）
  - 手動確認でクリックとキーボードの両方で転送・削除・非表示ができ、転送後も一覧の順序とウィンドウ表示が変わらない
  - _Depends: 5.2, 5.3_
  - _Requirements: 3.1, 6.1, 6.2, 6.3, 6.4, 6.7, 6.8, 6.10, 7.5, 11.5, 11.6_

- [ ] 5.5 設定ウィンドウを実装する
  - トレイまたはメニューから別ウィンドウとして開き、保持件数・ホットキー（キー入力を記録する UI）・タブ幅・ポーリング間隔（macOS / Wayland 以外は非表示）・自動起動・UI 言語を編集できる。転送オプションは含めない
  - 保存時にコマンドで更新し、範囲エラーはフィールド単位で、ホットキー競合はホットキー欄のエラーとして表示し、入力内容を保持したまま再入力を促す
  - 言語変更が再起動なしで両ウィンドウに反映される
  - 手動確認で保持件数を縮小すると一覧が即座に切り詰められ、無効なホットキーで直前の設定が維持される
  - _Depends: 4.4, 4.5_
  - _Requirements: 9.1, 9.3, 9.4, 9.6, 12.4_

- [ ] 5.6 更新の通知と承諾フローを実装する
  - updater プラグインを登録し、更新エンドポイントと公開鍵を設定に置く
  - 起動時に更新を確認し、あればバナーで通知する。承諾でダウンロード・適用し再起動を促す。拒否でバナーを閉じ現在のバージョンで継続する
  - 更新確認以外にネットワーク通信を行わない
  - ローカルで用意した更新マニフェストを指す設定でバナー表示・承諾・拒否の動作が確認できる
  - _Requirements: 13.6, 13.7, 13.8, 10.3, 10.4_

- [ ] 6. 統合・リリース・検証
- [ ] 6.1 macOS 上でエンドツーエンドの動作を統合確認する

  - 各転送モードとトグルの組み合わせで、貼り付け先に期待どおりの内容が入り、自身の書き込みが一覧に追加されない
  - パスワードマネージャからのコピーが一覧に出ない
  - 全 Rust テスト・全 Vitest・clippy・lint が通り、CI 3 ジョブが緑である
  - _Requirements: 1.1, 1.2, 1.4, 1.5, 1.8, 6.1, 6.5, 6.6, 7.4, 7.5, 7.6, 11.2_

  - テストタグでドラフトリリースが作成され、上記の資産がすべて揃っている

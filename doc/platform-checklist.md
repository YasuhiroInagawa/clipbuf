# プラットフォーム確認チェックリスト

自動テストで押さえられない項目を、リリース前に実機で確認するための一覧。CI（3 OS の lint / 型 /
テスト / ビルド）が緑であることを前提に、その上で人間が見るべきものだけを挙げる。

各項目は「操作 → 期待」の形で書いてある。期待どおりでなければ、要件番号を添えて issue にする。

## この記録について

チェックはこのファイルに直接入れてコミットする。リリースを出したらタグにその状態が残るので、
`git show v1.0.0:doc/platform-checklist.md` でその時点の確認記録を丸ごと取り出せる。次の
バージョンに入るときはチェックを戻し、下の見出しを書き換えてから埋め直す。

各行には**どこで確認したか**を添える（`（Windows で確認）` のように）。確認していない項目に
チェックを入れないこと。過大な記録は、薄い記録より役に立たない。

### 確認対象

| | |
|---|---|
| バージョン | 0.1.0（未リリース。最初の正式リリースは v1.0.0 を予定） |
| macOS | Apple Silicon / macOS 26.6.2。dev ビルドとローカル署名ビルド |
| Windows | 実機。CI がビルドした NSIS インストーラとアンインストーラ |
| Linux | GNOME (Wayland) の VM。CI がビルドした AppImage |
| 未確認の環境 | Intel Mac、X11、KDE Plasma (Wayland)、deb / rpm |
| 確認できなかった項目 | SmartScreen の警告（検証機のサードパーティ製 AV が Defender を置き換えていた） |

## 全 OS 共通

### 取り込み

- [x] ブラウザ・エディタ・ターミナルのそれぞれでコピー → **1 秒以内**に一覧の先頭に出る（1.1, 1.2）（macOS で確認）
- [x] ブラウザで**書式付き**の範囲をコピー → 「書式あり」の警告アイコンが付く（1.4）（macOS で確認）
- [ ] 同じテキストを続けて 2 回コピー → 一覧に 1 件しか増えない（重複排除）
- [ ] 保持件数（既定 20）を超えてコピー → 最古の項目が消え、件数が増え続けない（2.2）
- [x] パスワードマネージャでパスワードをコピー → **一覧に出ない**（1.8）。macOS ならパスワード
      マネージャがなくても確認できる: `swift scripts/macos-concealed-copy.swift "secret"`
      （macOS、上記スクリプトで確認）
- [x] clipbuf 自身で転送 → その内容が一覧に**新規追加されない**（1.5）（Windows / macOS で確認）

### 表示

- [ ] 改行を含むテキスト → 一覧は 1 行表示（改行は記号）、全文プレビューでは改行位置が見える（3.1）
- [x] 半角空白・全角空白・タブ・NBSP・ゼロ幅スペースを含むテキスト → それぞれ別の記号と色で出る
      （Windows の実クリップボードで確認。`clipboard_rs.rs` の唯一の生検証箇所）
- [ ] CRLF / LF / CR を混在させたテキスト → 色が 3 種類に分かれ、凡例がプレビュー下部に出る（3.7–3.9）
- [ ] 記号にポインタを合わせる → 何の文字かツールチップで分かる
- [ ] 警告アイコンにポインタを合わせる → 何が問題かツールチップで分かる

### 転送

- [x] 行をクリック → 緑のハイライト → 他アプリに貼り付けると期待どおりの内容（6.1）（macOS で確認）
- [ ] 「プレーン」ボタン → 転送オプションを適用した結果が貼り付けられる
- [ ] 「原文」ボタン（書式ありの項目のみ）→ 設定に関わらず無変換の内容が貼り付けられる（6.4.1）
- [ ] 転送後も一覧の順序と選択位置が変わらない（6.5）
- [x] 各トグル（書式保持 / 改行 / トリム / タブ→空白 / 全角空白→半角）の組み合わせで、
      プレビューの表示と実際に貼り付けられる内容が**一致する**（4.7）（macOS で確認）
- [x] 「書式を保持」をオンにして転送 → テキスト変換が適用されず、その旨の通知が出る（6.9）（macOS で確認）

### ウィンドウ・ホットキー

- [ ] グローバルホットキー（既定 `Alt+Shift+V`）で表示・非表示が切り替わる（8.2）
- [ ] 非表示から表示 → 最新の項目が選択されている（8.3）
- [ ] ↑↓ で選択移動、Enter で転送、Shift+Enter でプレーン転送、Delete で削除、Esc で非表示
- [ ] ウィンドウを閉じる操作 → アプリは終了せず非表示になる（8.5）
- [ ] 位置とサイズを変えて再起動 → 維持されている（8.6）
- [ ] 他アプリを前面にしても clipbuf が最前面に残る（8.1）
- [x] トレイ / メニューバーから 表示切替・設定・About・終了 ができる（8.4, 8.8）（Windows / macOS で確認）
      → Windows は左クリックで表示切替、右クリックでメニュー（設定/About/終了）

### 設定

- [ ] 保持件数を減らして保存 → 一覧がその場で切り詰められ、**その後のコピーでも増えない**（9.2）
- [ ] ホットキーを記録 → 記録中は現在のホットキーが効かない。保存後は新しいキーで動く（9.5.1）
- [ ] 他アプリが使っているホットキーを指定 → ホットキー欄にエラーが出て、入力が保持される（9.4）
- [ ] 保存 → 設定ウィンドウが閉じる。保存せず閉じる → 編集内容が破棄される（9.7, 9.8）
- [ ] UI 言語を切り替え → **再起動なしで**両ウィンドウに反映される（12.4）
- [ ] 同じ切り替えで**トレイメニューとウィンドウタイトル**も変わる（12.5）
- [ ] 日本語でも英語でもないロケールで起動 → UI・トレイともに英語（12.3）。**手順は OS で違う**:
      フロントは `navigator.language`、Rust は `sys-locale` を見るので、両者が何を読むかで決まる
      - Linux: `LANG=de_DE.UTF-8 npm run tauri dev` でよい
      - Windows: PowerShell で `$env:LANG` は効かない。設定 › 時刻と言語 › 言語と地域 で
        表示言語を変えるか、この項目は Linux 側の確認で代表させる
      - macOS: `LANG` では変わらない（どちらも `AppleLanguages` を見る）。リリースビルドを
        `open .../clipbuf.app --args -AppleLanguages '(de)'` で起動する。dev ビルドでは効かない
- [ ] 「ログイン時に起動」をオンにして再ログイン → 自動で起動し、ウィンドウは非表示のまま

- [x] 配布物の中に `LICENSE` と `THIRD-PARTY.md` が入っている（13.9）（macOS の .app 内 Resources で確認）

- [x] 「更新する」→ ダウンロード → 再起動を促され、再起動後に新しいバージョンになっている（13.7）（macOS、ローカルマニフェストで確認）

## Windows

- [ ] インストーラ実行 → SmartScreen の警告が出る。README の手順（詳細情報 → 実行）で起動できる（13.4）
      - **McAfee など、Defender を置き換えるサードパーティ製アンチウイルスが入っている端末では
        警告が出ないことがある**（SmartScreen の実行時保護がそちらに委譲され、OS 標準の
        ダイアログが表示されない）。この項目は Microsoft Defender が有効な端末で確認すること
- [x] インストール先が**管理者権限なし**で書き込める場所になっている（NSIS のユーザーインストール）
      → `%LOCALAPPDATA%\clipbuf`。インストール・再インストールを繰り返しても UAC
      昇格プロンプトは一度も出なかった
- [x] 設定画面に「ポーリング間隔」が**出ない**（Windows はイベント駆動）
- [ ] タスクバーに clipbuf のボタンが出ない（常駐アプリとして邪魔をしない）
      → `tauri.conf.json` の `skipTaskbar: true` はコードで確認済み。実機での目視は未実施
- [x] コマンドプロンプトからのコピー（CRLF）が正しく色分けされる
- [x] アンインストール後、設定ファイルの残骸を確認する
      - Tauri の NSIS テンプレートには「確認」画面に **"Delete the application data"** という
        チェックボックスが標準で付いている（既定は未チェック）。チェックを入れて
        アンインストールすると `%APPDATA%\jp.gr.mac.iyas.clipbuf` と
        `%LOCALAPPDATA%\jp.gr.mac.iyas.clipbuf`（`settings.json`・WebView2 のプロファイル）
        が削除される。チェックを入れずに残っているのは想定通りの挙動

## Linux — GNOME (Wayland)

- [x] 「Wayland で data-control が使えないため、ネイティブ Wayland アプリのコピーは取り込めないこと
      があります」がウィンドウ上部に表示される（11.5）（Ubuntu 22.10 GNOME/Wayland、VM で確認）
- [x] XWayland で動くアプリからのコピーは取り込める（同上、ターミナルからのコピーで確認）
- [x] ネイティブ Wayland アプリ（`GDK_BACKEND=wayland` 起動の GNOME テキストエディター。`xwininfo` で
      X11 のウィンドウツリーに存在しないことを確認済み）からのコピーも**取り込まれた**。Mutter が
      相互運用のため Wayland のクリップボードを X11 の `CLIPBOARD` セレクションへブリッジしており、
      X11 フォールバック中の clipbuf がそれを観測するため。バナーの「取り込めないことがあります」と
      いう表現（絶対に取り込めないとは言っていない）と矛盾しない
- [ ] グローバルホットキーが効かない場合、トレイまたはコマンドラインから起動して操作できる

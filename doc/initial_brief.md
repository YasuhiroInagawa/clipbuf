# clipbuf — 初期要件ブリーフ（/kiro-spec-init 用）

## 概要

GUI 環境でのコピー＆ペーストを補助するクリップボードバッファアプリ「clipbuf（仮称）」を作る。
他アプリでコピーされたテキストを自動で取り込んでリスト表示し、**貼り付け前に事故要因（書式・空白・改行・機種依存文字など）を可視化し、1 クリックで無害化してクリップボードへ戻す**ことが特徴。
既存のクリップボード履歴ツール（CopyQ, Clipy, Maccy, Ditto 等）との差別化は「可視化 + 警告 + 無害化転送」の 3 点にある。

無料・オープンソース（MIT）で GitHub Releases から配布する個人プロジェクト。販売しない。

## 対象プラットフォーム

- Windows / macOS / Linux のデスクトップ 3 OS。
- 技術スタックは **Tauri 2（Rust コア + Web フロントエンド）** を第一候補とする。理由：空白・改行の可視化は HTML/CSS が最も表現しやすい、バイナリが小さい、3 OS 向けのビルド・macOS 公証・インストーラ生成が公式 CI ワークフローで揃う、依存ライセンスが MIT/Apache-2.0 で再配布に障壁がない。
- Linux は X11 / XWayland を主対象とし、Wayland ネイティブは wlr-data-control 対応コンポジタ（KDE, wlroots 系）のみ。GNOME Wayland はフォーカス外のクリップボード読み取りが不可のため非対応と明記する。Flatpak はサンドボックスの制約があるため配布形態から外す（AppImage / .deb / .rpm）。

## 機能要件

### 1. クリップボード監視（取り込み）

- アプリ自身以外のウィンドウでコピーが行われたら自動で取り込む。実装は OS のクリップボード変化監視（Windows: `AddClipboardFormatListener`、macOS: `NSPasteboard.changeCount` のポーリング、X11: XFixes SelectionNotify）。
- 取り込み対象はテキストのみ。画像・ファイル等は無視する。
- テキストと同時にクリップボードに載っているリッチ形式（HTML / RTF）は「スタイル保持で転送」のために生データのまま保持する。
- 自分自身がクリップボードへ書き込んだ変化は取り込まない。
- パスワードマネージャ等の秘匿マーク（macOS `org.nspasteboard.ConcealedType`、Windows `ExcludeClipboardContentFromMonitorProcessing`、KDE `x-kde-passwordManagerHint`）が付いた内容は取り込まない。
- 履歴はメモリ上のみで永続化しない（終了時に消える）。機密が残らないことを既定にする。

### 2. リスト表示

- 取り込んだ項目を FIFO で保持し、最新の N 件（既定値は設定可能、例: 20）だけ残す。古いものから消える。
- 直前の項目と同一内容なら重複追加しない。
- 各項目は **1 行** で表示し、その右に警告アイコン列を並べる。行の幅の範囲で見せられる最大文字数を表示する。
  - 改行を含むテキストは、表示上は改行を取り除いて（改行記号に置き換えて）1 行に連結する。データ本体は改行を含んだまま保持する。
  - 等幅フォントで、以下を記号・色で可視化する：半角空白、全角空白（別記号・別色）、タブ、改行、NBSP・ゼロ幅スペース等の不可視文字
- 行のテキスト部分は編集不可だが、横スクロールで全文を見られるとなおよい。
  - 表示自体からのテキスト選択・コピーはできない（転送は行選択の操作で行う）。
  - その項目からフォーカスが外れたら、スクロール位置は先頭に戻る。
  - 読み取り専用テキストフィールドの一般的な挙動を想定しているが、フォーカスを持つコントロールにするかどうかで動きが変わるため、実装して調整する前提とする。
- 各項目の横に警告ステータス（アイコン列）を表示する：
  - スタイルあり（HTML / RTF 形式が同居）
  - 先頭または末尾に空白・改行あり
  - タブ文字あり
  - 機種依存文字あり（NEC/IBM 拡張文字等、JIS X 0208 外の判定）
  - 制御文字・不正サロゲート等のバイナリ的内容あり
  - 改行コードの混在（CRLF / LF / CR）、BOM、双方向制御文字、NFC/NFD 混在
  （「エンコーディング」警告は、クリップボード上のテキストが既に Unicode 化されているため、上記のような具体的検出項目として定義する）
- 項目の個別削除、全削除ができる。

### 3. クリップボードへの転送

- 行をクリック（またはキーボードで選択して Enter）すると、その項目をクリップボードへ書き戻し、他アプリでペーストできる状態にする。
- 転送時オプション（ウィンドウ上のトグルとして常時表示し、クリック 1 回で適用される）：
  - スタイルの保持 / 削除（削除時はプレーンテキストのみ書き込む）
  - 改行の処理：そのまま / 削除 / 空白に置換（英文で単語が結合しないように置換も用意する）
  - 先頭末尾の空白・改行のトリム
  - タブ → 空白変換
  - 全角空白 → 半角空白変換
- 行ホバーで代替アクション（「プレーンで転送」「元のまま転送」）のボタンを出す。
- 転送内容は元の項目を書き換えない（非破壊）。

### 4. ウィンドウ

- 常に最前面の小さなフローティングウィンドウ。グローバルホットキーで表示 / 非表示を切り替える。
- 画面端への固定（他ウィンドウが避けるドッキング）は macOS に標準 API がないため初期スコープ外。将来の拡張候補として設計上の余地だけ残す。
- システムトレイ / メニューバー常駐。

### 5. 設定

- 保持件数、ホットキー、転送オプションの既定値、ポーリング間隔（macOS）、起動時に自動起動するか。
- 設定のみ永続化する（履歴は永続化しない）。

## 非機能要件・制約

- 端末内で完結。ネットワーク通信は自動更新チェック以外行わない。
- 日本語 UI と英語 UI。
- 配布：GitHub Releases。GitHub Actions（`tauri-action`）で 3 OS 分をビルドし、タグ push でリリース添付する。
  - macOS：Developer ID で署名 + notarization（既存の Apple Developer Program を使う）。
  - Windows：コード署名しない（SmartScreen 警告は README で回避手順を案内）。winget / Scoop 対応は将来検討。
  - Linux：AppImage / .deb / .rpm。
- 自動更新は `tauri-plugin-updater`（GitHub Releases 配信、minisign 署名）を使う。
- macOS 26 以降のペーストボードプライバシー警告について README で案内する。
- 依存ライブラリのライセンス一覧（THIRD-PARTY）をビルド時に生成して同梱する。
- Releases に SHA-256 を併記する。

## 初期スコープ外

- 画像・ファイルの履歴
- 履歴の永続化・検索・ピン留め
- クラウド同期
- 画面端ドッキング
- Flatpak / Mac App Store / Microsoft Store
